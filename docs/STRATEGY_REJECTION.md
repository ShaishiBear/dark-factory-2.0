# Evidence-based strategy rejection

An authenticated factory refusal records what a particular worker reported. It does not
establish a cause. A separate deterministic assessment can now contradict a preregistered
assumption and reopen only the affected recommendation frontier.

## Supported operational claim

The first rule, `new-architecture-dependency-v1`, means precisely:

> This strategy requires a **new** dependency from the named source architecture layer to
> the named target layer, and protected architecture policy permits that new dependency.

This checks an existing governed constraint. It is not a generic diagnosis of performance,
quality, maintainability, infrastructure or implementation correctness. It does not reject
grandfathered existing dependencies or infer the strategy's required edges from code/prose.
The rule's declaration supplies the assumption's operational meaning; the independent
reader establishes the permission fact. Unrelated claims must not use this predicate.

The owner form and bounded reasoning service can register 1–8 rules, once per session,
before its first recommendation. Rules reference active assumption ancestors of recorded
candidates. They cannot be added after seeing a factory result. Relevant rules enter the
admitted strategy and programme hash. Historical v1.1 inputs without rules remain unchanged.
The rule set is shown before selection and in the programme publication payload.

## Independent findings and decisions

After importing an authenticated outcome, sessions with registered rules automatically
receive a separate assessment. The assessor independently reauthenticates the exact current
factory outcome and historical handoff. The protected Git reader then verifies the policy
blob, exact source commit, repository/protection/currency and executing authority/parser
source files. Its fixed paths cannot be selected by a model. It executes no candidate code
and accepts no caller-supplied findings, causal labels or verdicts.

A known layer-to-layer permission explicitly absent from the allowed imports is a
contradiction when policy enables new-edge enforcement. Unknown layers, malformed policy,
unavailable sources, changed revisions or mismatched authority code do not establish a
contradiction. A supported permission also leaves the strategy intact. The authority checks
only registered layer permissions; all other architectural and product proof obligations
remain with the ordinary independent factory authorities.

An assessment records the rules, independently established findings, authority source hashes,
policy hash, revision, affected claims and recommendation frontier. A contradiction
invalidates the linked assumption and flags affected recommendations for reconsideration.
Unrelated decisions, approved scope, retained alternatives and cumulative budgets remain
unchanged. The refusal's `failure_cause` stays `unresolved`: a separate policy counterexample
does not prove that it caused the observed build failure.

No assessment authorizes publication, dispatch, replacement, merge or proof reuse. Retained B
must be reconsidered within existing limits and receive fresh factory qualification.

## Recovery and owner interface

The original outcome and the assessment are separate canonical events. A crash, stop or CAS
conflict between them leaves an imported outcome with no assessment. The UI exposes **Check
registered assumptions**, which reauthenticates the current source and can explicitly retry
a missing/unresolved read. No paid effect is retried. Resolved assessments cannot be replaced
by a second decision for the same outcome. Exact command replay cannot invalidate twice.

`POST /api/exploration/register-rules` and `/api/exploration/assess-feedback` use existing
bearer authentication, same-origin enforcement, server-owned identity, CAS, stop and bounded
event storage. Registration requests contain `rules`; assessment requests contain only
`outcome_id`. The ordinary recovery command reopens the affected question; it preserves all
reservations, uncertain spend and maximum rounds.

## Completion limits

This implements an automatic rejection path for one concrete policy predicate. New predicate
families require reviewed independent authorities and detectors; arbitrary failure prose
cannot become a strategy verdict. Broader experiments and calibrated architecture judgments
remain separate work. The connected tests exercise real receipt/retention/import, protected
Git blob reading, causal assessment, retained-B reconsideration and state restoration with
synthetic platform responses. They are not a live hosted A-to-B qualification demonstration.
