# Stored strategy publication

The optional Front Door `--enable-strategy-publication` flag requires programme publication
and its authenticated currency service. It is disabled by default. Saved exploration
recommendations appear as private historical choices. Reviewing one regenerates a programme
v1.1 input from canonical owner records and freshly inspected protected repository context.
There is no endpoint for supplying arbitrary strategy text or provenance.

Owner consent binds the exact public input, repository visibility, approval, project version,
session, recommendation and handoff hashes. Private interview and approval wording stay in
the host store. Strategy rationale and uncertainty are part of the explicitly displayed
public input. Advice remains UNPROVEN and cannot supply product proof or bypass a certifier.

Reservation and currency checks regenerate the same input. Remote reads happen outside the
intent lock; the owner history and request lifetime are fenced again before returning.
The HTTP currency endpoint uses the publisher's configured request service. Encryption is
followed by another currency check before reserving the single workflow POST. Uncertain
effects remain durable and are never blindly retried. Protected publication jobs independently
validate the v1.1 input and hashes using the normal admission path.

An existing active programme still prevents a new publication, including a different strategy
for the same specification. This change does not implement governed replacement, proof reuse,
automatic reactivation or a budget reset. It creates no model calls, experiments, history
events, API credentials or cloud resources during review/regeneration.

Protected-context reads retain their existing limits. The 60-second currency challenge and
30-second HTTPS client timeout are unchanged. An inspection that does not fit fails closed;
one successful latency sample is not a service guarantee. Hosted exploration authoring and
deployment activation are separate work. A passing fixture is not a real App publication.
