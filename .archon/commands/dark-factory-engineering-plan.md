Use the preloaded `to-spec`, `domain-modeling`, and `codebase-design` skills as the engineering procedure. Explore the code before deciding design. Establish shared vocabulary, respect ADRs, choose observable test seams, prefer deep existing modules over new surface area, and make out-of-scope explicit.

This node does not publish tickets. Write `$ARTIFACTS_DIR/plan.md` containing problem, user-visible behaviour, implementation decisions, test decisions, likely files, risks, and out-of-scope. If requirements remain materially ambiguous, stop rather than manufacture a specification.
